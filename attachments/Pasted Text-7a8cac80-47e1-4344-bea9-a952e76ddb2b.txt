Round 1 is verified correct — clock-based timer (endsAt/pausedMs), useWakeLock,
skippedStepIds, minutes-from-completed-steps, versioned BackupV1, Disclaimer
placement. Don't undo any of it. These are the remaining gaps.

--- 1. Make "cautious" actually change the session (highest priority) ---

Problem: ClearanceGate asks about injury, surgery, dizziness. Answering
"Yes — I'll skip anything that hurts" sets clearance="cautious", shows one
sentence, then serves an IDENTICAL program — same steps, same durations.
Dizziness is a real contraindication for head-below-heart positions
(sl-hang "Ragdoll hang") and for end-range neck rotation (dr-look
"Slow look-aways"). Right now the screening records a disclosure instead of
changing the care.

Do:
- Add an optional flag to Exercise in types.ts:
    caution?: "inversion" | "neck-endrange"
- Tag in catalog.ts, at minimum: sl-hang -> "inversion";
  dr-look, dr-chin, mp-chin, fm-chin -> "neck-endrange". Use judgment on others.
- When clearance === "cautious", filter flagged steps from the program BEFORE
  the session starts, and cut remaining hold `seconds` by ~30%.
- If filtering drops the program below 3 steps, substitute unflagged steps of
  the same focus rather than running a 2-step session.
- Show what changed on the session screen: "Adjusted for caution — 2 steps swapped."

Acceptance: with clearance="cautious", a program containing sl-hang never
presents sl-hang.

--- 2. Make clearance date-scoped, not permanent ---

Problem: SCREENING_QUESTION ends in "...today?" but clearance is stored as
`Clearance | null` with no date, so one answer at the first-ever session governs
forever. CheckIn, right beside it in the same store, is already date-keyed.

Do:
- Store clearance keyed by todayKey(), mirroring CheckIn's shape.
- ClearanceGate shows whenever there is no entry for today.
- Bump BackupV1 -> BackupV2. parseBackup must accept BOTH: migrate a v1 bare
  `clearance` by DROPPING it (re-asking is safer than carrying a stale clearance).

Acceptance: answering on day 1 shows the gate again on day 2. Restoring a v1
backup file still succeeds.

--- 3. Confirm before an import wipes data ---

Problem: progress.tsx calls replaceFromBackup(JSON.parse(text)) directly from the
file input. Wrong file = entire history replaced, no undo — in the feature built
to protect that history.

Do:
- Parse and validate first, then show a confirm step with real counts:
  "Replace 43 sessions and 12 check-ins with 12 sessions and 4 check-ins?"
- Only write on confirm.
- Keep the existing "That file isn't a Plumb backup." message for parse or
  validation failure.

Acceptance: selecting a valid backup mutates nothing until the user confirms.

--- 4. Announce the timer to screen readers ---

Problem: TimerRing is aria-hidden and the countdown is a plain <span>, so a
screen reader announces nothing during a hold.

Do: add a visually-hidden aria-live="polite" region announcing the exercise name
at step start and "Hold complete" at zero. Do NOT announce every second.

--- 5. Verify backup download on a real phone (not a code change) ---

a.click() on a blob URL is reliable on desktop but flaky in an iOS home-screen
PWA, where it may open the JSON in a viewer instead of saving it. Test on the
actual device. If it fails, add a "Copy backup to clipboard" button beside the
download as a fallback.

--- Do not change ---

The exercise cues and coach copy. The conservative cueing ("Release 80%, not all
the way to the poke", "No forcing the last inch", "If the knees complain, pad
them") is the strongest part of the app.
